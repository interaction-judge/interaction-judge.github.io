Interaction-as-a-Judge

We study Interaction-as-a-Judge which uses computer-use agents to evaluate applications. We find that Interaction-as-a-Judge improves evaluation and also improves inference-time scaling (55.4% → 75.5%) and reinforcement learning with an interaction-only reward model.

We evaluate three computer-use methods

Better computer-use methods lead to richer interactions and better evaluations.

Heuristic Computer-Use (Random)
Actions sampled from the action space, no observation.
One-Shot Computer-Use
Sees one screenshot, then plans all actions up front.
Iterative Computer-Use
Observes the screen at every step before acting.

Finding 1: Interaction-as-a-Judge improves LLM and reward model alignment to human preferences

65.6%→69.1%
LLM judge accuracy
70.8%
Trained reward model

Iterative computer-use agents (GPT 5.6 Luna) improve human alignment compared to code-only and code+screenshot judges. Additionally, better computer-use methods lead to better performance. We also find that it’s possible to train a reward model on interactions alone.

Finding 2: Interaction-as-a-Judge helps models catch broken requirements

63.0%→71.1%
Broken requirement detection

We find that Interaction-as-a-Judge not only improves over LLM-as-a-Judge, but it also similarly scales with model performance.

Finding 3: Interaction-as-a-Judge allows for improved inference-time scaling

55.4%→75.5%
Requirements repaired

Interaction-based self-feedback repairs far more broken requirements than code-only self-feedback.

Finding 4: Interaction-as-a-Judge can be used in reinforcement learning

+6.7pp
Win rate vs base model
−35.7%
Generated code length
81.3%→88.5%
Build success

RL with an interaction-only reward improves Qwen-3.5-9B’s win rate by the equivalent of over +50 Arena leaderboard points. Additionally, it does so while both reducing build failures and also reducing code bloat.
